# Laboratory Activity 2: Build the Cloud Infrastructure Blueprint

## Mission Overview
This laboratory activity uses the KillerCoda Linux environment to investigate core cloud infrastructure components—specifically analyzing how compute, storage, networking, and operating systems interoperate to support cloud workloads. By executing native Linux diagnostic tools, It will evaluate system resource interactions and document all configuration data and technical findings into a professional.

## Objectives
- Explain the major components of cloud infrastructure
- Investigate the hardware and software resources available in a Linux environment
- Differentiate compute, storage, networking, and identity resources
- Create professional technical documentation using Markdown
- Continue building a structured GitHub Cloud Computing Portfolio

## Cloud Infrastructure Components
- **Compute Resources** – CPU and processing power
- **Storage Resources** – Disk capacity and file systems
- **Networking Resources** – IP address and network connectivity
- **Operating System** – Linux (Ubuntu)

## Tools Used
- KillerCoda Playground
- GitHub
- Linux Terminal
- draw.io (for the architecture diagram)
- Web Browser

## Linux Commands Executed
- `cat /etc/os-release`
- `uname -r`

- `nproc`
- `free -h`
- `df -h`
- `df -T`
- `hostname`
- `hostname -I`

## Skills Learned
- Mastered Linux CLI diagnostic tools (lscpu, top, df, ip addr) within the KillerCoda environment to audit compute resources, disk partitions, network interfaces, and IAM access controls. Developed practical expertise in analyzing how cloud subsystems interoperate during pre-deployment planning, mapping service equivalents across AWS, Azure, and GCP.
