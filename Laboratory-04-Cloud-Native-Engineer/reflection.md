# Mission Reflection

Traditional Virtual Machines require several minutes and significant system resources to load an entire guest operating system, whereas Docker containers launch in seconds by directly sharing the host machine’s kernel. This efficiency made me realize how much time and resources can be conserved when deploying applications with containers instead of VMs. Another important lesson was port mapping. When I deployed the Nginx container, I had to use -p 8080:80 to ensure that requests directed to my host’s port 8080 would be forwarded to port 80 inside the container. Without this mapping, the web server would remain isolated and inaccessible, which helped me understand how containers are secure by default and require explicit networking rules to connect them. I also discovered that when a container is removed using docker rm, all data inside it is erased unless volumes are configured. This highlighted the importance of planning for persistent storage in real-world applications. Containers are lightweight and temporary by design, which makes them perfect for stateless services that need to be deployed quickly and scaled easily. From a DevOps perspective, containerization changes the way developers and IT operations teams collaborate. Developers can package applications with all dependencies into a single image, while operations teams can deploy and scale that exact image consistently across environments. This eliminates the classic “it works on my machine” problem, reduces conflicts, and speeds up delivery. Documenting this mission in my GitHub portfolio strengthened both my technical skills and my confidence as a cloud-native engineer.
