# Mission Reflection

Automation is very important in managing hundreds of servers because it removes the dependency on human intervention. Also, The Manual processes are prone to error, delays and inconsistency while automation ensures that tasks such as backups, monitoring and deployments run reliably and on schedule. By automating tasks engineers can focus more on innovation and problem-solving rather than routine maintenance.

However automation also comes with dangers. A destructive typo or misconfigured script can cause damage if deployed across many servers. For example a wrong path or command could delete files or overwrite important data. This highlights the importance of testing, documentation and version control before rolling out automation at scale.

Writing a Bash script felt different compared to creating a Docker Compose YAML file in Mission 6. Bash scripting is imperative meaning you write step-by-step instructions for the system to follow. Docker Compose on the hand is declarative—you describe the desired state of services and Docker handles the orchestration. Both approaches are powerful. They require different mindsets when designing solutions.

Looking back, from Laboratory 1 to Laboratory 9 my understanding of Cloud Computing has transformed significantly. I started with concepts and gradually learned about infrastructure, cloud-native applications, data engineering, security and finally automation. Each mission built upon the one giving me a holistic view of how cloud systems are designed, deployed and maintained.

Among all the roles I enjoyed being the **Cloud Automation Engineer** the most. It combined scripting, scheduling and documentation which made me feel like I was truly eliminating error and improving efficiency. The sense of control and reliability that automation provides is. It aligns well with my goal of becoming a skilled cloud infrastructure engineer.
