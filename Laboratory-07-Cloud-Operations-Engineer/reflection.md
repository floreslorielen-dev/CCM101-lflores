# Mission Reflection 

This mission taught me the importance of observability in containerized environments. At first, I thought monitoring was only about checking if a container was running, but I realized that host resources matter just as much. Even if a container appears healthy, limited memory or disk space on the host can cause failures during heavy traffic. Establishing a baseline for CPU, memory, and disk gave me a clear understanding of the system’s capacity before deploying workloads. Using `docker logs` was eye‑opening. By simulating both successful and failed requests, I saw how logs capture every event, including the 404 error when accessing a non‑existent page. This reinforced the idea that logs are not just technical details but it is an important tools for troubleshooting. If a user reported login issues, I could trace the exact request and error in the logs, making the problem solve in time. I also learned the difference between logs and metrics. Logs tell the story of what happened, while metrics show how efficiently the system is performing.
