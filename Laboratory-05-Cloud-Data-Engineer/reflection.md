# Mission Reflection 

Using Docker made deploying the MinIO storage server much easier because it allowed me to run the service inside a container without worrying about manual installation or dependency conflicts. With a single command, I was able to pull the image, configure environment variables, and start the server. Docker’s portability also means the same setup can be replicated on different machines, ensuring consistency and reducing setup time.
A bucket in cloud storage is essentially a logical container where objects (files) are stored. Buckets help organize data and provide a namespace for managing files. In this mission, creating the client-photos bucket allowed me to group all uploaded images in one place, making management and access straightforward.
To ensure object storage data is not lost if the physical server crashes, enterprise companies use techniques such as replication, redundancy, and backups. Data is often distributed across multiple servers, so even if one server fails, copies of the data remain accessible. This resilience is one of the key advantages of cloud-based object storage systems. My confidence in navigating the Linux command line has grown significantly through this mission. Running Docker commands, verifying containers, and accessing ports required me to use Linux tools more fluently. Each step reinforced my ability to troubleshoot and execute commands effectively, and I now feel more comfortable working in a cloud engineering environment.
